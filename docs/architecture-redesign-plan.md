# Rose Audit 架构重做方案

## 目标与状态

将审计作为 Spring Boot 基础设施能力提供。标准 MVC 业务请求、受支持的认证流程、定时任务和消息监听入口自动采集审计事实；应用通过 Provider、Consumer 和显式记录接口提供自定义语义。

入口适配器采集事实，共享核心生成不可变事件，投递模块负责异步消费。请求处理结果、认证结果和后台执行结果分别定义，不由通用框架推断业务事务是否成功。

本文记录目标设计与当前实现状态。保留现有扩展点和 JDBC 查询能力；事件结构、结果枚举和事务语义的变化按显式版本迁移处理。实现状态与尚未完成的验收项见下文。

## 实施状态（2026-10-23）

已完成首轮实现：事件分类、事件 ID 与未知结果；Servlet 请求过滤和 MVC 路由快照；请求范围、异步完成和异常结果处理；Security 标准认证事件适配；后台任务/消息事件分类；事务外异步消费；PostgreSQL schema 更新和 V2 迁移；README、CHANGELOG 与示例更新。

本轮验证：全模块 `mvn test` 和 `mvn package` 通过（包括 PostgreSQL Testcontainers 集成测试，sample Boot Jar 完成重打包）；`mvn spotless:check` 和 `git diff --check` 通过。Tomcat 随机端口测试覆盖容器 `sendError`、未处理异常、ERROR 后转发、真实 Spring Security Basic 认证成功/失败、JWT Provider 成功事件、MVC 前拒绝、异步完成和异步超时；PostgreSQL 测试验证 V2 对有存量行的旧 Schema 回填；执行器关闭等待与失败日志限流有独立测试。HTTP 完成状态现在串行化处理并保留首个失败，另有并发完成单测。JWT 测试使用桩 decoder，只验证 Security Provider 到审计事件的衔接，不验证 JWT 签名或真实 issuer 配置。未运行 release profile 的签名或发布。

尚未完成的验收项：

- Tomcat 已验证 ERROR 后 FORWARD 不产生重复请求事件，以及异步完成/超时；其他容器对 ERROR dispatch 的差异、重复 ERROR 分派和客户端取消时的回调行为未覆盖。完成状态的并发单测已覆盖，但没有模拟容器并发回调。
- 队列拒绝与消费失败已验证隔离；日志每 10 秒最多输出一条并累计被抑制数量，默认不重试。
- 会话恢复、OIDC 登录和应用自定义/MFA 流程没有统一的标准认证尝试事件；需要应用按业务登录/登出事实显式调用 Recorder。此版本要求同一流程只选择标准事件或 Recorder 之一；标准监听和 Recorder 共存及尝试级去重暂不支持。

因此，本文中的设计目标与验收要求仍是后续检查基准；未列为已完成的项目不应视为已支持。

## 设计范围

- 首版先完成 Servlet/MVC、上下文快照和投递，再接入 Security，最后整理调度和消息入口。
- 默认采用有界内存队列、尽力而为投递；持久化 Outbox 单独设计。
- 不自动采集完整请求体、方法参数、返回值、实体快照或字段差异。
- 不引入通用插件注册器、插件生命周期或业务侧 `@Enable...` 注解。
- 首版不覆盖 WebFlux、WebSocket 消息或任意框架的异步返回类型。

## 模块职责

沿用现有 Maven 模块，先按包隔离职责，不预建空模块。

| 模块 | 职责 |
| --- | --- |
| `rose-audit-spring-boot-autoconfigure` | 公共事件和扩展接口、上下文快照、事件规范化、入口适配、投递与条件自动配置 |
| `rose-audit-spring-boot-jdbc` | JDBC Consumer、查询、PostgreSQL Schema 与迁移说明 |
| `rose-audit-spring-boot-starter` | 聚合默认使用所需依赖 |

核心保留小接口：应用提供 Actor、Tenant、Correlation 等 Provider，或替换 `AuditEventConsumer`；特殊流程使用显式记录接口。事件构建、完成竞争和队列处理属于内部实现。

适配器只识别入口、贡献上下文和报告结果，不各自实现存储、事务回调或重试。仅在独立依赖管理或发布确有需要时拆出集成模块。

自动配置同时检查运行环境、classpath 和启用配置。Servlet 仅在 Servlet Web 应用启用，MVC、Security 和消息集成分别隔离。非 Web 应用可使用核心与后台入口；可选类型不得泄漏到无条件加载的配置类签名中。

## 事件模型

保留不可变事件和现有上下文字段，新增 `eventId`、事件类型与 `UNKNOWN` 结果。eventId 标识单条事件，requestId 关联同一请求中的不同事件，两者不互相替代。

| 类型 | action 示例 | Outcome 含义 |
| --- | --- | --- |
| HTTP 请求 | `POST /orders/{id}/cancel` | 请求处理结果 |
| 认证 | `authentication.login` | 一次认证尝试的结果 |
| 定时任务 | `OrderJob.closeExpiredOrders` | 一次入口执行结果 |
| 消息监听 | `OrderListener.onCreated` | 一次消息处理尝试的结果 |

HTTP action 优先使用方法与路由模板；配置纳入的非 Controller 端点使用方法与配置匹配模板，避免动态 ID 进入操作名称。首版不增加任意属性 Map；对象标识等扩展按实际需求另行设计。

`occurredAt` 表示开始时刻，耗时使用单调时钟计算。无法获知开始时间的认证事件使用结果观察时刻，耗时标记为未知，不伪装成精确零毫秒；具体字段表示随公共事件迁移确定。

### HTTP Outcome

按以下优先级判定：

1. 未处理异常、异步超时或可观察到的传输写入失败为 `FAILURE`，即使响应已提交为 200。
2. 正常完成且最终状态为 4xx/5xx 时为 `FAILURE`。
3. 正常完成且最终状态为 2xx/3xx 时为 `SUCCESS`。
4. 无法可靠确定完成结果时为 `UNKNOWN`。

4xx 表示请求未成功完成，不表示服务故障。HTTP 200 响应体中的业务错误不由框架解析；需要该语义的应用使用显式业务事件。

经 MVC 解析并转为正常响应的异常，不自动视为未处理异常。首版不承诺捕获所有已解析异常的类型或消息。

httpStatus 保存可观察到的实际状态，不由 Outcome 反推。异常尚未经过容器处理时，默认 200 不视为最终状态。请求处理成功也不证明客户端完整接收了响应。

## HTTP 请求生命周期

### 统一入口与上下文

在 Spring Security 链之前注册外层 Servlet Filter，覆盖 Security 或后续 Filter 提前结束的请求。相对顺序通过自动配置和集成验证固定；更早执行的其他 Filter 短路不在可观察范围内。

内部 `HttpAuditState` 存入 request attribute，保存开始时间、关联标识、路由、身份与租户快照、异常和完成状态。明显排除的请求提前跳过；依赖 MVC 路由判断的请求可先创建轻量状态，但未纳入范围时不构造或投递事件。

MVC 拦截器只补充 HandlerMethod、路由模板和上下文。移除现有 Advisor 的 MVC 发布路径，避免两条路径同时记录请求；后台入口适配另行保留和整理。

### 单次完成

所有完成路径汇入同一内部模块，原子状态转换保证一个逻辑请求最多提交一次事件。该约束仅保证单次提交尝试，不保证持久化成功。

- 普通同步请求：在确认无后续异步或错误处理的终止点完成。
- 异步请求：初始 Filter 返回时不发布；错误和超时回调先记录事实，完成时统一提交。重新开始异步周期时继续关联原状态并注册所需监听。
- 同步异常与 sendError：Filter 链返回时提交；sendError 提供的状态作为请求结果，未处理异常优先判为失败。此时容器后续错误页可能改变响应内容，但不产生第二条事件。
- ERROR dispatch：复用原请求状态，不独立生成事件；错误 Controller 不替换原业务 action。
- FORWARD/INCLUDE：归入原逻辑请求，以首次选定的业务入口为 action，不因内部转发增加事件。
- 重复分派、重复通知和完成竞争：只有一次状态转换能提交事件。

OncePerRequestFilter 本身不提供跨所有分派的单次完成保证。dispatcher types、异步支持和完成监听必须配套配置。同步 sendError 以 sendError 指定的状态记录；ERROR dispatch 复用已完成状态，避免重复事件。异步请求由完成监听发布；无法确认最终状态时使用未知值，不提前记录成功。

请求销毁兜底不得在请求有效期结束后读取 Servlet 对象。完成后释放请求、响应和异常引用；队列只保存不可变事件。不缓存完整响应体。

### 长连接

SSE、流式下载在实际结束时记录，不把首个响应字节视为结束，不周期性生成完成事件。进程崩溃时未结束请求可能没有记录。

客户端断连仅在容器暴露写入异常等信号时记录失败。WebSocket 握手后的消息需要独立适配，不沿用 HTTP 完成模型。

## 上下文快照

Provider 在上下文仍有效时执行并立即形成快照；完成回调和 Consumer 不再读取线程局部上下文。

- MVC 在进入业务处理时采集 Actor、Tenant、Correlation。
- Security 在认证结果发生时采集身份，不依赖外层 Filter 返回后的 SecurityContextHolder。
- 非 Controller 的自定义 Filter 若需贡献身份或业务语义，使用专用请求上下文接口；没有可靠来源时保留空值。
- 异步线程仅贡献明确属于该请求的数据，不读取线程池残留身份；后台入口不得误用残留 HTTP 上下文。
- 同一请求保持稳定关联标识；外部 request ID 限制长度和字符，trace ID 单独保存。
- 请求 actor 表示执行身份。认证失败的输入用户名属于未经验证的声明，不写入已认证 actor 字段；确需保存时使用独立、默认关闭且受脱敏限制的字段。
- 登出等流程保留清理前的执行身份，不在请求完成时用空身份覆盖快照。

Provider、规范化和发布的普通运行时失败由审计模块隔离并计数，不覆盖业务返回或原始异常；不承诺隔离 JVM 致命错误。

## 范围与敏感信息

范围规则按以下优先级执行：

1. 匹配有效排除规则则跳过。
2. 匹配额外包含规则则纳入，包括非 Controller 端点。
3. 实际命中业务 Controller 则纳入。
4. 其他请求跳过。

默认排除健康检查、静态资源、监控、文档和真实 CORS 预检，不笼统排除所有 OPTIONS。默认排除集合可通过显式配置替换；有效集合内排除始终优先。匹配使用统一语法和应用内路径，避免 context path 导致失效。

Security 在 MVC 前拒绝的请求没有实际命中的业务 Controller，仅在额外包含规则覆盖时记录，不提前执行 MVC 路由推断范围。ERROR 属于原请求生命周期，不作为新请求重新筛选。

保留当前 query string 默认关闭行为，错误消息也默认关闭。开启查询参数采集时采用允许列表和长度限制，不直接存储原始查询串。凭据、Cookie、Authorization 和完整载荷不采集。

无路由模板时原始路径也可能包含敏感值，action 使用配置模板，原始 URL 按采集规则处理。User-Agent 等外部输入限制长度并清理控制字符。客户端 IP 使用容器提供的地址，不自行信任任意转发头；可信代理由部署配置管理。

## 认证适配与去重

认证结果独立记录，通过 requestId 与 HTTP 事件关联。一条请求事件和一条认证事件属于两类事实。

当前支持矩阵：

| 流程 | 自动事件覆盖 | 状态和边界 |
| --- | --- | --- |
| Spring Security ProviderManager 的 HTTP Basic | 成功与失败 | 已由 Tomcat 集成测试验证；应用需发布标准认证事件 |
| Spring Security OAuth2 Resource Server Bearer JWT | ProviderManager 可发布的认证结果 | 已验证成功事件到达审计监听器；集成测试的 decoder 为桩实现，不代表 JWT 签名或发行方配置已验证 |
| SecurityContext 会话恢复 | 不产生新的认证尝试事件 | 如需记录本次会话登录/恢复语义，由应用显式记录；普通请求仍有 HTTP 事件 |
| OIDC 登录、自定义 Provider、MFA | 依流程是否发布标准认证事件 | 当前未验证完整流程；应用应显式记录需要的业务语义，并避免与标准事件重复记录 |

标准适配器只记录可靠观察到的认证结果。某种认证类型在 classpath 中，不代表流程一定发布标准成功/失败事件。

同一认证流程必须选定一个结果记录来源：标准适配器或手动 AuditAuthenticationRecorder。当前版本不支持同一流程同时启用两种来源，也不提供尝试级去重。不能按 requestId 丢弃第二次结果，一个请求可能包含多次尝试；如果后续需要共存，先为每次尝试定义共享标识，再实现去重。

认证不一定发生于 HTTP 请求，无法关联时保留独立事件。适配器不强制依赖 Servlet，也不读取凭据对象的字符串表示或直接记录原始失败消息。

## 后台入口与事务

请求、认证、任务执行与消息处理都是已经发生的执行事实。默认不因业务事务回滚而删除，也不因发布时偶然存在的事务改变保留规则。

移除当前 Listener 对全部事件统一实施的“成功只在提交后投递、回滚丢弃”策略。适配器明确各自观察点：

- HTTP 在请求处理完成后提交事件。
- 认证在结果被可靠观察时提交事件。
- 调度和消息在受支持的执行完成点提交事件；方法返回不自动等同于外层事务提交、消息确认或业务成功。
- 重试按每次执行尝试分别记录，不误判为重复；消息标识与事件标识分开。

后台 AOP 的事务顺序、类级监听注解和异步返回类型必须定义支持范围。尚未适配的 Future、Publisher 等不得在方法返回时伪报最终成功。

提交后才成立的业务事实使用显式业务记录能力，另行定义提交后发布策略；首版不新增通用事务模式开关。需要业务数据与审计原子持久化时再设计 Outbox，并单独处理回滚或失败事实。

## 投递与可靠性

通过统一内部入口提交不可变事件，经有界队列调用 AuditEventConsumer。是否保留现有 Spring 事件通知路径，先盘点调用方再决定；同一事件只能有一条 Consumer 投递路径。

- 队列满时拒绝并计数，不在请求线程执行 Consumer。
- Consumer 失败计数并输出受控日志，默认不重试。
- 关闭应用时给予有限排空时间，报告未完成数量。
- 构建失败、排队拒绝、消费失败和成功均可观察；指标标签不含用户、请求、动态路径或任意 action 等高基数值。
- 日志不打印完整事件或可能含敏感信息的原始异常消息，故障持续时控制日志数量。
- 不承诺严格事件顺序；查询使用时间和唯一标识形成稳定排序。
- 审计自身的存储和运维入口不参与自动业务审计；自定义 Consumer 不得递归产生同类事件。

进程崩溃、队列溢出、消费失败、关闭超时和请求未结束都可能丢事件。默认模式不保证持久化、至少一次或恰好一次投递；数据库故障不能改变原业务响应。

## 破坏性变更与数据迁移

本次重设计不提供旧 Java API 的源码或二进制兼容：不保留旧事件构造器、弃用构造器或旧 MVC 发布路径。应用需迁移到新的事件结构和入口行为。Provider/Consumer 扩展点及 JDBC 查询能力仍属于当前设计，不作为兼容层保留。以下变化必须显式说明：

- HTTP action 从类名/方法名变为方法/路由模板。
- HTTP 耗时从方法时长变为请求处理时长。
- Outcome 按事件类型解释并新增 UNKNOWN。
- 执行事实不再因事务回滚统一丢弃。
- 新增事件标识、分类及必要的未知耗时表达。
- 认证失败输入用户名不再冒充已认证 actorName。

实施前检查公共 record 构造器、自定义 Consumer、Spring 事件监听器、查询 DTO、序列化和 SQL 约束。提供版本说明、迁移 SQL 和示例；自动配置不得静默修改数据库。

历史类型不能根据 action 猜测，使用历史未知分类或可空值。历史 eventId 回填、非空和唯一约束由迁移脚本定义。新字段、UNKNOWN 与未知耗时同步更新 JDBC 写入和查询映射。

先迁移 Schema 再部署新写入端。升级脚本是 `classpath:db/audit-schema-postgresql-v2.sql`，不放在 Flyway 默认的 `db/migration` 下，依赖本身不改库。若旧实例不能读取新枚举或空耗时，不承诺混合版本滚动升级：先停止旧写入端，再迁移，然后启动新版本。旧 MVC 发布路径与新 Filter 不得同时启用。

## 实施顺序

1. 盘点工作区、公共接口、订阅方、Schema 和测试，确定迁移清单。
2. 固定事件分类、Outcome、时间与未知值表示，完成 JDBC 迁移设计。
3. 在真实容器验证 sendError、异常、ERROR、异步与多次分派，再实现统一完成模块。
4. 接入范围规则和 MVC 快照，替换旧 MVC AOP 发布路径。
5. 调整事务无关的事实投递、队列策略、故障计数和关闭处理。
6. 接入认证适配与 Recorder 迁移，再整理调度和消息完成语义。
7. 更新 README、配置、迁移文档和支持矩阵，完成针对性验证。

## 验收条件

- MVC 业务请求无需审计注解或显式调用；范围外请求不投递。
- 包含/排除、context path、预检和非 Controller 端点遵守规则。
- Security 短路、MVC 异常解析、sendError、嵌套 ERROR、转发、异步 redispatch/完成/超时竞争均不重复提交；可用时采集最终状态，不把中间 200 当作最终成功。
- Security 清理、线程切换和复用后身份与租户不串请求；未知身份保持未知。
- 认证成功/失败、无 HTTP 认证、多次尝试及手动/标准来源共存符合规则。
- 提交与回滚都保留相应执行事实；方法返回、事务提交与消息确认的区别有测试和文档支持。
- 队列拒绝、Consumer/Provider 失败和关闭超时不改变业务响应或原异常，且有计数。
- 可选依赖缺失不影响核心启动；应用 Provider/Consumer 可覆盖默认 Bean。
- 凭据和完整载荷不采集，查询参数允许列表、日志脱敏和长度限制有效。
- 历史数据可查询，升级顺序有说明，不声称未经验证的二进制兼容、滚动升级或持久化保证。

以上为实施验收要求，文档更新不代表检查已经执行。

## 框架依据

- [Spring OncePerRequestFilter](https://docs.spring.io/spring-framework/docs/7.0.0-RC1/javadoc-api/org/springframework/web/filter/OncePerRequestFilter.html)：异步与错误分派需要单独配置，不能凭类名推断整个逻辑请求只执行一次。
- [Spring Security Servlet Authentication Architecture](https://docs.spring.io/spring-security/reference/servlet/authentication/architecture.html)：请求结束时 SecurityContext 会被清理，身份需在有效期内形成快照。
